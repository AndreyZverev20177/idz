# 🎵 Music Analytics — анализ музыкальных треков

Учебное Python-приложение, которое принимает CSV-файл с музыкальными треками, очищает данные, считает статистику по прослушиваниям и показывает результаты двумя способами:

- **Streamlit** — интерактивная веб-страница с таблицами, показателями и графиками;
- **FastAPI** — HTTP API, которое принимает тот же CSV-файл и возвращает результат в JSON.

Проект создан как самостоятельное решение для учебного задания по разработке программных средств: «входные данные → проверка → расчёт → осмысленный результат». В приложении нет базы данных, Telegram-бота, автоматической выгрузки из музыкальных сервисов и запросов к внешним музыкальным API. Каждый анализ выполняется для **конкретного загруженного CSV**.

> **Проверено:** 23 автоматических теста (`pytest`) прошли в доступном Python-окружении. Сборка Docker-образа, открытие Streamlit в браузере и проверки Black/Flake8 в контейнере требуют отдельного запуска на компьютере или в CI.

## 1. Возможности приложения

- Загрузка CSV с треками через браузер или HTTP-запрос.
- Проверка обязательных столбцов, размера файла, кодировки и корректности строк.
- Подсчёт исходных, корректных и исключённых строк, а также пропусков.
- Вывод среднего количества прослушиваний за месяц.
- Фильтрация популярных треков по задаваемому порогу прослушиваний.
- Рейтинг исполнителей по сумме прослушиваний с учётом совместных треков.
- Статистика жанров: число треков, суммарные и средние прослушивания.
- Графики популярных треков и средних прослушиваний по жанрам в Streamlit.
- Машинно-читаемые результаты по HTTP, автоматически сформированная документация OpenAPI.

## 3. Архитектура и движение данных

```text
Пользователь
   │
   ├── Браузер → Streamlit (app.py, порт 8501) ───────┐
   │                                                  │
   └── HTTP-клиент → FastAPI (main.py, порт 8000) ───┤
                                                      ▼
                             utils/data_loader.py: приём и очистка CSV
                                                      │
                                                      ▼
                             utils/analysis.py: расчёты, рейтинги, графики
                                                      │
                            ┌─────────────────────────┴─────────────────────┐
                            ▼                                               ▼
                 Таблицы и графики                                     JSON-ответ API
```

**Важное архитектурное решение:** Streamlit **не отправляет запросы к FastAPI**. Это две самостоятельные точки входа в одну библиотеку обработки данных. Поэтому можно запускать только интерфейс, только API или оба процесса. База данных и внешние сервисы не требуются.

Слои приложения:

1. **Ввод / представление:** `app.py` для человека, `main.py` для внешнего клиента.
2. **Валидация:** `utils/data_loader.py` — проверка CSV, очистка ошибок и диагностика качества.
3. **Бизнес-логика:** `utils/analysis.py` — расчёты и построение графиков.
4. **Контракты:** классы `Track`, `Artist`, `Genre`, `AnalysisResponse` в `main.py` описывают JSON API.
5. **Тестирование:** `tests/` проверяет расчёты, входные данные и ответы API.

### Разбор ключевых файлов

**`app.py` — пользовательский интерфейс.** Настраивает страницу Streamlit, принимает CSV через `file_uploader`, обрабатывает ошибку загрузки, показывает количество корректных и исключённых строк, метрики и таблицы. Ползунок/поле порога прослушиваний влияет и на таблицу, и на диаграмму популярных треков. Функции анализа импортируются из `utils`, чтобы не дублировать алгоритмы.

**`main.py` — HTTP API.** Создаёт объект `FastAPI`, описывает четыре Pydantic-модели и два маршрута. Метод анализа проверяет расширение имени файла, размер содержимого, параметры запроса, передаёт CSV в общую функцию и преобразует таблицы Pandas в обычный JSON-ответ.

**`utils/data_loader.py` — проверка входных данных.** Содержит константы `REQUIRED_COLUMNS` и `MAX_UPLOAD_BYTES`; исключение `DataValidationError`; объект `LoadedData` с данными и диагностикой; функции `read_csv_bytes()` и `load_data()`. Это место для изменения правил качества данных.

**`utils/analysis.py` — аналитика.** Содержит функции `get_data_info()`, `get_popular_tracks()`, `calculate_mean_listens()`, `parse_artists()`, `get_artist_rating()`, `get_genre_statistics()`, `plot_genre_popularity()` и `plot_popular_tracks()`. Основные расчёты не зависят от Streamlit или FastAPI.

**`music_analysis.py` — модуль совместимости.** Не реализует расчёты заново: переэкспортирует функции из `utils`, чтобы старые импорты `from music_analysis import ...` продолжали работать.

**`Dockerfile` — сборка контейнера.** Использует `python:3.12-slim`, устанавливает зависимости, копирует рабочие исходники и задаёт Streamlit как стандартную команду. Для API тот же образ запускается с переопределённой командой `uvicorn`.

**`requirements.txt` / `requirements-dev.txt`.** Первый нужен работающему приложению, второй подключает первый файл и добавляет инструменты тестирования и стиля. Поэтому Docker-образ приложения не содержит pytest, Black и Flake8.

**`tests/conftest.py`.** Хранит фикстуры — одинаковые входные данные для разных тестов, чтобы избежать копирования CSV и таблиц по тестам.

**`tests/test_analysis.py`.** Проверяет выбор популярных треков (включая граничный порог), среднее, рейтинги, безопасный разбор исполнителей и график.

**`tests/test_data_loader.py`.** Проверяет допустимый CSV, отсутствие столбцов, пустой файл, плохие строки, файл без корректных записей, лимит размера и CP1251.

**`tests/test_api.py`.** Использует FastAPI `TestClient`: проверяет `/health`, успешный анализ, неверное расширение, повреждённый CSV, недопустимый порог, слишком большой файл и наличие метода в OpenAPI.

**`pyproject.toml`.** Устанавливает длину строки Black (88 символов), целевой Python 3.12 и каталог поиска тестов `tests`.

**`.gitignore` и `.dockerignore`.** Не включают в репозиторий/контекст сборки временные кэши, виртуальные окружения и локальные секреты. В `.dockerignore` отдельно исключены `tests` — производственному образу они не нужны.

**`.github/workflows/tests.yml`.** При публикации GitHub проверяет проект в Linux-окружении: устанавливает dev-зависимости, выполняет pytest, Black и Flake8. Наличие файла само по себе не означает, что workflow уже прошёл успешно.

**`data/sample_tracks.csv`.** Пример входного формата для первой проверки. Результаты анализа этого файла ниже используются в примерах API.

## 5. Формат входного CSV и правила очистки

### Обязательные столбцы

Имена должны совпадать **точно** (включая скобки в `artist(s)`). Порядок столбцов может быть любым, дополнительные столбцы допускаются.

| Столбец | Тип после загрузки | Пример | Значение |
|---|---|---|---|
| `name` | Текст | `Northern Lights` | Название трека |
| `genre` | Текст | `Pop` | Жанр |
| `artist(s)` | Текст / строковое представление списка | `['Aster', 'Bloom']` | Один или несколько исполнителей |
| `monthly_listens_total` | Число (приводится к `float` при обработке) | `2500000` | Прослушивания за месяц |

Пример CSV:

```csv
name,genre,artist(s),monthly_listens_total
Northern Lights,Pop,"['Aster', 'Bloom']",2500000
After Midnight,Jazz,['Saxland'],450000
Fresh Air,Pop,['Bloom'],1530000
```

Если внутри ячейки есть запятая (например, два исполнителя), всю ячейку нужно заключить в двойные кавычки, как в первой строке примера.

### Ограничения и обработка

- Формат — CSV с разделителем **`,`**.
- Поддерживаются UTF-8, UTF-8 с BOM и CP1251. Кодировка пробуется сначала как `utf-8-sig`, затем как `cp1251`.
- Максимальный размер входного файла — **10 МиБ (10 × 1024 × 1024 байт)**.
- Если отсутствует хотя бы один обязательный столбец, анализ прерывается с ошибкой.
- Строка исключается, если `name`, `genre` или `artist(s)` отсутствует/пуст после удаления пробелов.
- Строка исключается, если `monthly_listens_total` нельзя преобразовать в число, число отрицательно или не является конечным (например, `NaN`, `inf`).
- Значение **0 прослушиваний допустимо**.
- Если после фильтрации не осталось корректных строк, анализ прерывается с ошибкой.
- `total_rows` — количество строк до очистки; `valid_rows` — после очистки; `dropped_rows` — разница.
- `missing_values` — количество пропусков, обнаруженных **в исходной таблице до очистки**; пустая строка не всегда будет учтена Pandas так же, как пропущенное значение.
- Некорректные строки исключаются **целиком**, не исправляются автоматически; причина каждой строки отдельно не возвращается.

> Примечание: API проверяет расширение **имени файла `.csv`**, но не проводит отдельную проверку MIME-типа содержимого. Поэтому само расширение не гарантирует, что содержимое корректное: это проверяет парсер.

## 6. Логика расчётов

| Расчёт | Правило |
|---|---|
| Среднее за месяц | Сумма `monthly_listens_total` / число корректных треков |
| Популярные треки | `monthly_listens_total >= min_listens`; сортировка по убыванию |
| Рейтинг исполнителей | Сумма прослушиваний всех треков исполнителя; сортировка по убыванию |
| `tracks_count` исполнителя | Число строк-треков, в которых он указан |
| Статистика жанра | Число треков, сумма и среднее прослушиваний по жанру |
| График жанров | Столбчатая диаграмма **среднего**, а не суммарного числа прослушиваний |

Если в `artist(s)` записан список `['Aster', 'Bloom']`, то каждому из двух исполнителей засчитывается **полное** число прослушиваний трека, а не половина. Из-за этого суммарные прослушивания по всем исполнителям могут превышать сумму по уникальным трекам. Это **принятое правило расчёта**, а не ошибка.

Для списков исполнителей используется `ast.literal_eval` — содержимое CSV не выполняется как Python-код. Если строка не разбирается как список, она считается одним именем исполнителя.

## 7. Запуск без Docker

Нужен установленный Python 3.12 (или совместимая версия), доступ к `pip`, а также терминал **в корне проекта** — там, где лежат `app.py`, `main.py` и `requirements.txt`.

### Windows PowerShell

```powershell
cd "C:\Projects\idz_reviewed\idz"  # замените на свою папку
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app.py
```

Если команда `py -3.12` отсутствует, но установлен подходящий Python, можно заменить её на `python -m venv .venv`. Если PowerShell блокирует активацию скриптов, можно не активировать окружение и вызывать `\.venv\Scripts\python.exe -m pip ...`, `\.venv\Scripts\python.exe -m streamlit run app.py`.

Открыть интерфейс: **http://localhost:8501**.

Чтобы отдельно запустить API, открой **второй терминал** в этой же папке и выполните:

```powershell
.\.venv\Scripts\Activate.ps1
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Документация API: **http://localhost:8000/docs**.

### Linux / macOS

```bash
cd /path/to/idz
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
# В другом терминале с тем же окружением:
# uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

## 8. Подготовка Windows 10/11 и WSL 2

Эта часть предназначена для **Docker Desktop на Windows**, в том числе Windows 10 с Legacy BIOS. **Устанавливать Ubuntu не требуется:** Docker Desktop использует собственное Linux-окружение в WSL 2.

Перед установкой проверьте:

1. Windows 64-bit и совместимость её редакции/сборки с вашей версией Docker Desktop. Системные требования: https://docs.docker.com/desktop/setup/install/windows-install/.
2. Аппаратная виртуализация включена в BIOS: «Диспетчер задач → Производительность → ЦП → Виртуализация: Включено». Для Intel настройка может называться `Intel Virtualization Technology / VT-x`, для AMD — `SVM Mode / AMD-V`.
3. WSL 2 установлен и активен. В **PowerShell от имени администратора** при необходимости:

   ```powershell
   wsl --install --no-distribution
   wsl --update
   wsl --set-default-version 2
   ```

   Если включение компонентов Windows требует перезагрузки — перезагрузитесь. Для уже установленного WSL эти команды могут не понадобиться.
4. Проверка состояния:

   ```powershell
   wsl --version
   wsl --status
   ```

5. Установите Docker Desktop с https://docs.docker.com/desktop/setup/install/windows-install/ и запустите его. При необходимости убедитесь, что выбран движок WSL 2 (`Settings → General → Use WSL 2 based engine`); на поддерживаемой системе опция может быть включена автоматически и не отображаться.
6. В PowerShell выполните:

   ```powershell
   docker --version
   docker info
   docker run --rm hello-world
   ```

   Ожидаемое окончание тестового запуска: `Hello from Docker!`.

**Если BIOS работает в Legacy-режиме.** Для включения виртуализации используйте клавишу BIOS при включении компьютера (часто `Del` или `F2`, зависит от платы). Команда `shutdown /r /fw /t 0` может не работать в Legacy-режиме. **Не переключайте Legacy на UEFI ради Docker:** это не требуется и может нарушить загрузку Windows.

Полезная справка Docker: https://docs.docker.com/desktop/features/wsl/.

Если файлы находятся в другой вложенной папке, перейдите именно в неё. **Точка (`.`) в команде сборки означает текущую папку.**

### 9.2. Соберите Docker-образ

```powershell
docker build -t music-analytics:latest .
```

Docker последовательно:

1. Загружает базовый образ `python:3.12-slim`.
2. Устанавливает переменные окружения Python и Matplotlib.
3. Создаёт рабочую папку `/app` внутри контейнера.
4. Копирует `requirements.txt` и устанавливает рабочие зависимости через `pip`.
5. Копирует `app.py`, `main.py`, `music_analysis.py`, `utils/` и `data/`.
6. Запоминает стандартную команду запуска Streamlit на порту 8501.

Проверка, что образ создан:

```powershell
docker images music-analytics
```

На первой сборке нужен интернет для загрузки базового образа и библиотек. В сборку не включены `tests/` — это задано в `.dockerignore`.

### 9.3. Запустите Streamlit

```powershell
docker run --rm -d --name music-ui -p 127.0.0.1:8501:8501 music-analytics:latest
```

Расшифровка:

- `--rm` — удалить контейнер после остановки, **не удаляя образ**;
- `-d` — запустить в фоновом режиме;
- `--name music-ui` — название контейнера;
- `-p 127.0.0.1:8501:8501` — порт 8501 компьютера направить на порт 8501 контейнера; доступ только с этого компьютера;
- `music-analytics:latest` — ранее собранный образ.

Откройте **http://localhost:8501**, загрузите `data/sample_tracks.csv`, проверьте таблицы и графики. CSV выбирается через браузер **с диска Windows**: копировать файл в контейнер не нужно.

### 9.4. Запустите FastAPI в отдельном контейнере

```powershell
docker run --rm -d --name music-api -p 127.0.0.1:8000:8000 music-analytics:latest uvicorn main:app --host 0.0.0.0 --port 8000
```

Здесь после имени образа передаётся **другая стартовая команда**: вместо Streamlit запускается Uvicorn с приложением `app` из файла `main.py`. Адрес `0.0.0.0` внутри контейнера нужен, чтобы порт был доступен через Docker. `EXPOSE 8501` в Dockerfile — метаданные, он не запрещает явно опубликовать порт 8000 при запуске API.

Проверка:

```powershell
docker ps
curl.exe http://localhost:8000/health
```

Откройте **http://localhost:8000/docs** — Swagger UI. Альтернативные страницы: `/redoc` и `/openapi.json`.

### 9.5. Логи, остановка и повторный запуск

```powershell
# Показать оба контейнера и их порты
docker ps

# Посмотреть журнал работы
docker logs music-ui
docker logs music-api

# Следить за журналом API в реальном времени
docker logs -f music-api

# Остановить только наши два сервиса
docker stop music-ui music-api
```

Если контейнеры были созданы с `--rm`, после остановки они удалятся. **Образ останется.** Для повторного запуска выполните команды `docker run` из пунктов 9.3 и 9.4. Если **изменили исходный код**, сначала пересоберите образ командой `docker build -t music-analytics:latest .`, затем создайте новые контейнеры (старые контейнеры сами не обновляются).

Чтобы выключить сам Docker Desktop, выберите **Quit Docker Desktop** в меню его значка в системном трее. Команда `wsl --shutdown` отдельно выключает все окружения WSL — используйте её только при необходимости.

### 9.6. Запуск на другом внешнем порту

Если порт 8501 уже занят:

```powershell
docker run --rm -d --name music-ui -p 127.0.0.1:8502:8501 music-analytics:latest
```

Тогда интерфейс открывается по адресу **http://localhost:8502**. Одновременно можно держать только **один контейнер с одним и тем же именем** `music-ui`.

## 10. Все API-контракты

### Общие сведения

- **Базовый адрес локально:** `http://localhost:8000`.
- **Формат ответа:** `application/json`.
- **Документация:** `GET /docs` (Swagger UI), `GET /redoc` (ReDoc), `GET /openapi.json` (генерируемая спецификация OpenAPI). Эти страницы предоставляет FastAPI автоматически.
- **Авторизация:** отсутствует — проект ориентирован на локальную демонстрацию.
- **Хранение данных:** файл обрабатывается во время запроса; загрузка в БД и долговременное хранение не реализованы.

### 10.1. `GET /health`

**Назначение:** простая проверка доступности процесса API (liveness).

Параметров нет, тело запроса отсутствует.

```http
GET /health HTTP/1.1
Host: localhost:8000
```

Успешный ответ — **HTTP 200**:

```json
{
  "status": "ok"
}
```

Этот маршрут не проверяет состояние Docker, качество CSV или работу Streamlit — только то, что API отвечает на запрос.

### 10.2. `POST /api/v1/analyze`

**Назначение:** проверить CSV-файл и вернуть статистику и рейтинги.

**Тип тела запроса:** `multipart/form-data`, обязательное поле с именем **`file`**. JSON в теле вместо файла не принимается. Название загружаемого файла должно заканчиваться на `.csv` (без учёта регистра).

| Имя | Где передаётся | Тип | Обязательно | По умолчанию | Ограничения |
|---|---|---|---|---|---|
| `file` | `multipart/form-data` | Бинарный CSV-файл | Да | — | Имя `.csv`, размер не более 10 МиБ, обязательные столбцы и ≥1 корректная строка |
| `min_listens` | Query-параметр URL | `integer` | Нет | `1000000` | `>= 0`; фильтр **включительный** (`>=`) |
| `top_n` | Query-параметр URL | `integer` | Нет | `10` | От 1 до 100 включительно |

`top_n` ограничивает массивы **`popular_tracks` и `artists`**, но **не `genres`**: по жанрам возвращается весь набор агрегированных групп. Параметр `min_listens` используется для `popular_tracks`, но рейтинги исполнителей и жанров рассчитываются **по всем корректным строкам**, а не по отфильтрованным популярным трекам.

#### Контракт успешного ответа — HTTP 200

| Поле JSON | Тип | Значение |
|---|---|---|
| `total_rows` | `integer` | Количество входных строк до очистки (без строки заголовка) |
| `valid_rows` | `integer` | Число строк, оставшихся после очистки |
| `dropped_rows` | `integer` | Число исключённых строк |
| `missing_values` | `integer` | Число пропусков в исходной таблице |
| `average_listens` | `number` | Среднее прослушиваний по корректным трекам |
| `popular_tracks` | `array<Track>` | До `top_n` треков, удовлетворяющих порогу |
| `artists` | `array<Artist>` | До `top_n` исполнителей по сумме прослушиваний |
| `genres` | `array<Genre>` | Статистика по **всем** жанрам корректных треков |

**Модель `Track`:**

| Поле | Тип | Значение |
|---|---|---|
| `name` | `string` | Название трека |
| `genre` | `string` | Жанр |
| `artists` | `string` | Исходное текстовое содержимое колонки `artist(s)` (не массив) |
| `monthly_listens_total` | `number` | Прослушивания данного трека |

**Модель `Artist`:**

| Поле | Тип | Значение |
|---|---|---|
| `artist` | `string` | Имя исполнителя |
| `total_listens` | `number` | Сумма прослушиваний по его трекам |
| `tracks_count` | `integer` | Число треков, в которых указан исполнитель |

**Модель `Genre`:**

| Поле | Тип | Значение |
|---|---|---|
| `genre` | `string` | Название жанра |
| `total_listens` | `number` | Суммарные прослушивания треков жанра |
| `mean_listens` | `number` | Средние прослушивания треков жанра |
| `tracks_count` | `integer` | Количество треков жанра |

#### Ошибки и коды ответа

| Код | Когда возвращается | Пример тела |
|---|---|---|
| `400 Bad Request` | Имя файла отсутствует или не оканчивается на `.csv` | `{"detail":"Нужен файл .csv"}` |
| `413 Payload Too Large` | Тело файла превышает 10 МиБ | `{"detail":"CSV больше 10 МБ"}` |
| `422 Unprocessable Entity` | CSV пуст, повреждён, в нём отсутствуют столбцы либо не осталось корректных строк | `{"detail":"CSV-файл пуст."}` или другое диагностическое сообщение |
| `422 Unprocessable Entity` | Не передан обязательный файл или недопустимы `min_listens`/`top_n` | Автоматическая ошибка валидации FastAPI (в `detail` — **массив** объектов ошибок) |

Конкретная структура автоматических ошибок валидации может различаться между совместимыми версиями FastAPI/Pydantic. Актуальную **машинно-читаемую** спецификацию следует смотреть в `/openapi.json`.

## 12. Автоматические тесты и качество кода

### Без Docker

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m black --check app.py main.py music_analysis.py utils tests
python -m flake8 app.py main.py music_analysis.py utils tests --max-line-length=88 --extend-ignore=E203,W503
```

На подготовленной версии выполнен `pytest`: **23 теста прошли**. Выполнение Black/Flake8 должно быть отдельно подтверждено локально или в GitHub Actions.

### В Docker: отдельный тестовый образ

Обычный образ намеренно **не содержит** `tests/` и dev-инструменты. Чтобы проверить проект, создайте в корне файл `Dockerfile.test`:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt requirements-dev.txt ./
RUN pip install --no-cache-dir -r requirements-dev.txt
COPY . .
CMD ["python", "-m", "pytest", "-q"]
```

**Внимание:** в `.dockerignore` исключена директория `tests`; для тестового образа её нужно временно разрешить. Самый простой способ — скопировать `.dockerignore` в `.dockerignore.backup`, убрать из `.dockerignore` строку `tests` на время сборки, а затем восстановить исходный файл. Не коммитьте временное изменение без необходимости.

```powershell
docker build -f Dockerfile.test -t music-analytics-test .
docker run --rm music-analytics-test
```

### GitHub Actions

Workflow `.github/workflows/tests.yml` запускается на события `push` и `pull_request` и выполняет pytest, Black и Flake8 на Python 3.12. Статус выполнения смотрите на вкладке **Actions** после публикации репозитория.

## 13. Типичные ошибки и решения

| Симптом | Возможная причина | Действие |
|---|---|---|
| `docker` не распознаётся | Docker Desktop не установлен или CLI отсутствует в `PATH` | Запустить Docker Desktop, открыть новый PowerShell, проверить `docker --version` |
| `Cannot connect to Docker daemon` | Движок Docker не работает | Открыть Docker Desktop и проверить `docker info` |
| `Virtualization is disabled in firmware` | VT-x/AMD-V отключена в BIOS | Включить виртуализацию в BIOS и перезагрузить ПК |
| Ошибка WSL о компонентах Windows | Не включены WSL / Virtual Machine Platform или требуется перезагрузка | Проверить WSL, включить компоненты и перезагрузиться |
| `shutdown /r /fw /t 0` не работает | Компьютер работает в Legacy BIOS | Входить в BIOS клавишей при включении; **не менять Legacy/UEFI без необходимости** |
| `Cannot locate Dockerfile` | Терминал открыт не в корне `idz/` | Выполнить `Get-ChildItem Dockerfile` и `cd` в нужную папку |
| `port is already allocated` | Порт 8501/8000 занят | Остановить старый контейнер или сменить внешний порт (`8502:8501`) |
| `container name already in use` | Существует контейнер с таким именем | `docker ps -a`, затем остановить/удалить нужный контейнер или выбрать другое имя |
| Streamlit не открывается | Контейнер завершился или порт не опубликован | `docker ps -a`, `docker logs music-ui` |
| API на 8000 недоступно | Запущен только Streamlit | Отдельно запустить `music-api` с командой `uvicorn` |
| API вернул 400 | Загружен не `.csv` | Проверить имя файла и расширение |
| API вернул 413 | Файл >10 МиБ | Уменьшить файл |
| API вернул 422 | Нет столбцов, нет пригодных строк или неверные параметры | Посмотреть поле `detail`, проверить контракт из раздела 10 |
| Код изменился, но в Docker видна старая версия | Образ/контейнер не пересозданы | `docker stop ...`, `docker build ...`, затем снова `docker run ...` |

Для диагностики Docker обычно достаточно `docker ps -a`, `docker logs <имя>` и `docker info`. Удалять каталог `AppData\Local\Docker\wsl` **не следует**: там могут быть рабочие данные контейнеров и образов.
